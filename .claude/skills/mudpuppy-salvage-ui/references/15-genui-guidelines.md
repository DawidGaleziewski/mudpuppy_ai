# 15 · Generative UI guidelines: how the Workbench composes screens

> **The assistant chooses the view. The data fills it. The person decides.**

These rules apply to the Workbench (beta) and to any later place where the assistant composes part of a screen.
Behaviour per path and the rollout plan are in `14-workbench.md`. Every component, its props and markup are in
`16-genui-components.md`. The pipeline, the htmx decision and security are in `17-genui-architecture.md`.
Colour meanings come from `03-colour-guide.md`; gen UI adds no new colour.

Files: `design-system/css/genui.css` (classes, loads after `salvage.css`) · `workbench/schema/` (the contract the model
must follow) · `design-system/genui-components.html` (live examples) · `screens/wb-01…wb-10` (the Workbench designs).

---

## 1. Principles

| # | Principle | What it means | Why |
|---|---|---|---|
| 1 | **Catalogue, not canvas** | The model picks components from a fixed catalogue (`catalogue.json`, 15 types) and binds them to data by id. It never writes HTML, CSS or layout. | Every view that can appear was designed, tested and checked for accessibility. There is no markup to inject. |
| 2 | **The model chooses, the data speaks** | Pages, steps, counts, routes and screenshots come from the data lane (scan events, the portal model). The model's own words are limited to narration, the `why` line, suggestions and command reasons, and narration cites its events. | No invented numbers. Live updates never wait for the model. |
| 3 | **Provenance is always visible** | Every generated frame says it is generated and what its data is ("From events up to 10:58:44Z"). Each view (one spec) answers "Why this view?" and asks "Right view?" once, on its lead frame. | People trust what they can check, and only as far as they can check it. |
| 4 | **Stable over clever** | The same request gives the same view. Component ids persist across updates, changes happen in place, and layout comes from the path and the rollout phase. | People build a mental map of the screen. Movement destroys it. |
| 5 | **The person stays in charge** | The assistant proposes a path, views and commands. The person switches, dismisses and confirms. Every write asks first. | The assistant can be wrong; the cost of a wrong write is higher than one extra click. |
| 6 | **Calm by default** | At most four components per view, one announcement per milestone, no motion beyond the pulse and the caret, and focus never moves on its own. | A crawler produces events every second. The screen must not. |
| 7 | **Degrade gracefully** | A bad spec drops the bad part. If nothing is left, the answer is plain chat. If the model is down, the live map still updates. If the stream drops, the data stays with a notice. | The Workbench must never be worse than the chat it replaces. |
| 8 | **One source of truth** | Classes live in `genui.css` and `salvage.css`. The contract is generated by `workbench/tools/gen_wb_schema.py`. Words follow this doc. Prompts and templates never redefine any of them. | Prompts drift. Schemas and stylesheets are tested. |

## 2. Visual language

Gen UI reuses the Salvage Yard paints with one extra rule: **line style says who made it.**
Dashed blueprint means the assistant chose or wrote it. Solid means it was observed, or a person confirmed it.

| Element | Treatment | Class | Example |
|---|---|---|---|
| Generated view (the arrangement is chosen by the assistant; the data inside is observed) | Solid plate frame + dashed blueprint "generated" mark | `.sy-genview` + `.sy-genmark` | LIVE MAP `generated` ■ RUNNING |
| Generated card inside the conversation (phase 1, and the Chat path always) | Same, compact padding | `.sy-genview.sy-genview--card` | The live card under "Starting a map scan…" |
| A generated view that reports a real failure (ErrorCard) | Solid red edge, red title naming what failed + genmark | `.sy-genview.sy-genview--failure` | NEXT ACTION FAILED AT /KONTAKT `generated` ✕ FAILED (the scan itself: □ STOPPED) |
| A side sheet the person opened by clicking | Plain plate: no genmark, no Why (the person chose it) | `.sy-sheet` | /KALKULATOR/KIEROWCA · STEP 1 × |
| The assistant's reasoning | Dashed blueprint rule, blueprint tint (≤10%) | `.sy-genwhy` | "Because: You asked to map the OC/AC calculator." |
| Narration (the assistant's words about events) | Dashed blueprint left rule, mono times, a citation per line | `.sy-narration` + `.sy-cite` | 10:55:12Z Same URL, new screen: recorded as step 2. `step 102` |
| Raw events (observed) | Solid, mono times, no rule | `.sy-evtail`, `.sy-evstrip` | 10:58:44Z element not found (10 s) |
| Suggested follow-up | Dashed blueprint button | `.sy-suggest > button` | Where does it go next? |
| A write the assistant proposes | Dashed blueprint card, marker Confirm | `.sy-cmd[data-cmd-state="proposed"]` + `.sy-btn--primary` | RESUME FROM LAST CHECKPOINT · Confirm |
| Send (composer, command bar) | Chalk edge, never marker | `.sy-btn--strong` | Send |
| A finished or stopped live card, after a newer card arrived | Folded to its one-line summary + Expand | `.sy-genview--card` + `aria-expanded` on Expand | LIVE MAP `generated` □ STOPPED · 171 / 400 steps · 17 pages · 113 queued · Expand |
| The write is running | Solid cyan edge, running status | `.sy-cmd[data-cmd-state="running"]` | ■ Running |
| The write is done | Solid green edge, ok status | `.sy-cmd[data-cmd-state="done"]` | ■ Done · Resumed as scan 01a110e7-2068 |
| The write failed | Solid red edge, failed status | `.sy-cmd[data-cmd-state="failed"]` | ✕ Failed · ERR-… · nothing changed |
| The write was undone (marks only) | Solid line, ash title | `.sy-cmd[data-cmd-state="undone"]` | □ Undone · mark removed |
| The person cancelled, or the proposal no longer applies | Folded to one muted head line | `.sy-cmd[data-cmd-state="cancelled"]`, `[data-cmd-state="expired"]` | Cancelled · nothing changed / No longer applies: 01a110d5-2028 was resumed from Scans |
| A view is being composed | Dashed blueprint frame, skeleton blocks at final size, caret | `.sy-genview[data-gen-state="composing"]`, `.sy-genskel`, `.sy-genstatus` | Composing view_ |
| The live stream dropped | Dashed ash frame, notice strip, data stays readable; status "Not live" (dashed grey), meter neutral, last page "Last seen here" | `.sy-genview[data-gen-state="stale"]` + `.sy-genview__notice` + `data-status="unobserved"` | Live updates paused at 10:57:05Z · Reconnecting_ |
| Where the crawler is now | 2px cyan edge + running status "Crawler here" | `.sy-node[data-state="here"]`, `.sy-film__item[data-state="here"]` | /kalkulator/kierowca ■ CRAWLER HERE |
| The page where the crawler failed | 2px red edge + failed status | `.sy-node[data-state="failed"]`, `.sy-film__item[data-state="failed"]` | /kontakt ✕ FAILED HERE |
| Visit order | Inverse chalk badge | `.sy-order` | 1, 2, 3 … |
| Pages queued, not visited yet | Dashed ash tile / node | `.sy-film__item[data-state="frontier"]`, `.sy-node[data-state="frontier"]` | +113 queued |
| Path picked by the assistant | Dashed blueprint square before the reason | `.sy-pathswitch__why[data-source="assistant"]` | Picked by the assistant: you asked to map. |
| Path picked by you | Filled chalk square | `.sy-pathswitch__why[data-source="you"]` | You switched to Troubleshoot. |
| What the next message is about | Raised chip, control edge, mono | `.sy-ctxchip` in `.sy-ctxbar` | @ /kontakt · step 171 |
| Selected item | 2px chalk weld | `aria-pressed="true"`, `aria-current="true"` | Selected node, selected view |
| A person's words | Manila + typewriter | `.sy-note` | Never generated, never in a generated view |

**Rules**

1. **A generated view of observed data is solid.** "Generated" describes the arrangement, never the facts. Never draw a live map,
   a meter or a screenshot dashed because the assistant placed it.
2. **Blueprint is always dashed** (`03` §4.3), and in gen UI it always means "the assistant chose or wrote this".
3. **Marker is for the one decision on screen.** In the Workbench, **Send is always `.sy-btn--strong`** (Enter sends), never
   the marker primary. The marker goes to the single decision the screen is waiting for: **Confirm** in a command card, or
   **Open in Review** on a finding (decisions are made in Review). With no decision waiting, the Workbench has no marker
   button at all.
4. **Red only for real failures:** an action that failed (the ErrorCard, `.sy-genview--failure`, titled by what failed:
   "Next action failed at /kontakt"), a failed attempt, a failed command. The scan's own status stays **Stopped**
   (`data-status="stopped"`, ash), as `03` §4 rule 5 asks. Not red: a view that couldn't be built, a dropped component, a stale
   stream ("Not live", dashed grey) or a "No" in feedback. "Assistant down" keeps its header status (`failed` + ERR reference,
   `03` §6), but the Workbench stage does not turn red.
5. **Cyan only for now:** the crawler's position, a running scan, a running command. Never for "new" or "highlighted".
6. **Manila never on generated content.** Notes, overturned explanations and tags written by people stay manila; the assistant
   never writes on manila.
7. **No "AI look".** No sparkle icons, gradients, glows, robot avatars or rainbow borders. The word "generated" does that job.

## 3. Layout and stability

### 3.1 Layout belongs to the path and the phase

The model never chooses layout. The server places each component from its catalogue entry (`catalogue.json` → `placement`).

| Layout | Used by | Class | Columns |
|---|---|---|---|
| Inline | **Chat path, always** · every path in phase 1 | `.sy-wb.sy-wb--inline` | conversation (generated cards inside) · side sheet 320px. With no sheet open: one conversation column, at most 960px |
| Split | Mapping, Troubleshoot, Explain from phase 2 | `.sy-wb.sy-wb--split` | conversation 300–380px · stage |
| Focus | Mapping, Troubleshoot, Explain in focus mode (phase 3) | `.sy-wb.sy-wb--focus` | stage + command bar · side column 280px |

- **Chat always answers inline.** A chat answer is read in the conversation, so its cards sit in the conversation whatever the
  phase. Mapping, Troubleshoot and Explain take the layout of the current phase; switching from Chat to Mapping in phase 2
  opens the stage.
- **The side sheet exists only while it is open.** With no sheet the server renders `.sy-wb--inline.sy-wb--nosheet`: one
  readable column of at most 960px. Opening a sheet adds the 320px column (and drops `--nosheet`).
- **Phase 1 shows only what the person has.** The Path switch lists Chat and Mapping only; "Not what you need?" lists only
  available paths; there are no Troubleshoot buttons and no `@` hints until phase 2.
- Desktop only for the beta: 1280 is the reference and 1024 the floor. Under 1100px inline and focus become one column;
  under 1024px split stacks with the conversation first (`genui.css` responsive block).

### 3.2 Rules

- **Limits per view:** Chat 2 components, Mapping 4, Troubleshoot 4, Explain 3 (the schema enforces them).
- **Reserve space before content arrives.** A composing view takes its final size at once (`.sy-genskel__block` with
  `--sy-skel-h` set to the real component's height). Miniatures have a fixed height (`--sy-mini-h`), the graph canvas a
  fixed size from the server's layout. Nothing below a view moves when its content lands.
- **The console loader is not the assistant's skeleton.** Outside generated views (console pages, lists, pictures, the live
  map before its first page) loading uses `.sy-loader` in steel with the words of what loads, and boxes of their final size
  (`20-navigation-and-canvases/T-10`, T-14). Blueprint `.sy-genskel` stays reserved for "the assistant is composing this".
- **Never reflow under the cursor.** New items append where the eye expects them: filmstrip to the right, narration and
  event tail at the bottom, map nodes into the reserved canvas. If a new view spec arrives while the pointer is over the stage
  or focus is inside it, do not swap: show a notice in the view (`.sy-genview__notice`) "New view ready · Show".
- **Keep ids stable.** Each component in a spec has a required `id` ("map", "detail"), unique within the view (a duplicate is
  dropped as `duplicate_id`). On the page the frame's id is scoped by turn, `t{turn}-{id}` (`t43-map`), because cards from
  several turns share one log. A later view that keeps a component (same spec id and binding) is swapped in place onto the
  existing frame, so follow and selection survive; a new id inserts at the end; a missing id is removed after the turn. Never
  re-render a whole stage to change one prop.
- **One Why, one feedback per view.** "Why this view?" and "Right view?" sit on the view's lead frame (its first component).
  The other frames of the same view carry only the genmark and the source line.
- **Side trips fold.** Pages the crawler visited off the main route fold into a chip on the page they came from
  ("+2 side pages"), so the map and the filmstrip show the route, not every detour.
- **No surprise scroll.** The conversation sticks to the bottom only if the person is already at the bottom. Follow mode
  scrolls the graph canvas inside `.sy-graph`, never the page. Nothing scrolls a view into sight on its own.
- **Updates appear in place, without motion.** Values change, nodes appear, lines are added. The only motion is the running
  pulse and the caret (`04` §2.6). No slide, fade, flash or "new" highlight. Reduced motion stops both loops.
- **Compact inside the conversation.** Cards use `.sy-genview--card`; full views use the stage. A view never stretches the
  conversation column wider.
- **Old live cards fold.** Once a live card's scan has stopped or finished and a newer card arrives below it, the older card
  folds to its one-line summary ("Scan 01a110d5-2028 · 171 / 400 steps · 17 pages · 113 queued · stopped at /kontakt") with an
  **Expand** button (`aria-expanded`, `aria-controls` the card body). A running card never folds; folding never moves focus,
  never removes the card or its id, and Expand restores it in place until the person folds it again.
- **Long conversations trim from the top.** When earlier messages are trimmed, the log starts with a
  `.sy-chat__divider` "N earlier messages" that loads them on request. Trimming never removes the newest live card, a waiting
  command card, or the message the person is reading.

## 4. Writing for gen UI

The inventory voice of `04` §4 applies: counts first, then the next move. Plain words, short sentences, active voice.
Routes and ids as stored. Polish portal text exactly as captured, in quotes.

### 4.1 Narration

- **Past tense, what happened.** Start with the verb: Opened, Followed, Filled, Recorded, Queued, Stopped.
- **One line per page** (or per milestone). Never one per event.
- **Cite every line.** Each line ends with at least one `.sy-cite` linking to its event (`01a110d5-2028-7000-8f3e-5c1a9b27d460#102` → "step 102", title "Event 01a110d5-2028#102").
- **Numbers only from events.** Every number in a line must appear in a cited event. The server checks; a failing line is
  replaced by the templated line for that event.
- **No speculation.** If the cause is unknown, say what was observed, say that the cause is unknown, and point to where to look.
- **No self-talk.** No "I think", "Let me", "As an AI", "I'm excited to".

| Don't | Do |
|---|---|
| Navigated successfully to the car insurance section of the portal! | Followed 'Samochód' in the menu to /ubezpieczenia/samochod. `step 38` |
| The calculator seems to have a multi-step wizard, probably 3 steps. | Same URL, new screen: recorded /kalkulator/kierowca as step 2. `step 102` |
| Found about 40 links on the comparison page. | Back on /, followed 'Porównaj produkty' to /porownanie. 97 links queued. `step 140` |
| The contact form is broken because of a JavaScript error. | The next action's element wasn't there after 10 s. The cause isn't known yet; Troubleshoot shows the page at step 171. `step 171` |

### 4.2 The `why` line

- One sentence, at most 140 characters, about the person's request or the situation, not about the model.
- Shown next to the Path switch and in "Why this view?".

| Don't | Do |
|---|---|
| I have determined that a live map is the optimal visualisation for this task. | You asked to map the OC/AC calculator. |
| Showing troubleshooting tools as an AI assistant. | You asked why the scan stopped at /kontakt. |
| Here's a view! | The scan stopped at /kontakt. |

### 4.3 Suggestions

- At most 3, each at most 60 characters, phrased as the person would send it.
- Grounded in the view: a question about what is on screen, or the next move.
- Never generic ("Tell me more", "Anything else?"). Never a hidden write: a suggestion that leads to a write produces a
  command card first.

Good: "Why did it stop here?" · "Troubleshoot with me" · "Skip /logowanie this time" · "Which visits had the banner?"

### 4.4 Command cards

- **Title** = the command label, verb first: "Resume from last checkpoint", "Run an attempt", "Add a mark".
- **Body** says what will change, what will not, where it runs, and whether it can be undone, as facts (`.sy-facts`), then
  the assistant's one-sentence reason.
- **After:** say the result in one line with ids. Done: "Resumed as scan 01a110e7-2068, continues 01a110d5-2028." Failed: "Couldn't
  resume: ERR-… Nothing changed. Try again or troubleshoot." Undone (marks only): "Mark removed."

Example (fixture):

| Fact (in this order) | Words |
|---|---|
| Title | Resume from last checkpoint |
| Starts | a new scan that continues 01a110d5-2028 |
| From | /porownanie · step 140, last good checkpoint |
| Kept | 17 pages, 113 queued links |
| Where | sandbox |
| /kontakt | one more try with the original action (after troubleshooting: "recorded without submitting") |
| Undo | Not undoable. You can stop the new scan. |
| Reason | The page loaded but the form's button never appeared. |

Cancelled: the card folds to one muted line, "Cancelled · nothing changed". Expired (10 min, or its preconditions changed):
"No longer applies: 01a110d5-2028 was resumed from Scans".

### 4.5 Errors, fallbacks and empty states

| Situation | What the person sees | Words |
|---|---|---|
| Spec invalid, or no view fits | The chat answer alone. Nothing else. | — (logged with the drop reason) |
| One component dropped (unknown id, not allowed on this path) | The rest of the view + a notice in it | "One part of this view isn't available: the page isn't in scan 01a110d5-2028." |
| The model is down | Composer line; the live map keeps updating; header status Assistant down | "Assistant unavailable. The live map still updates." |
| The stream dropped | Stale frame + notice (not a live region); status "Not live", last page "Last seen here"; data stays | "Live updates paused at 10:57:05Z · Reconnecting_"; the notice goes on reconnect |
| The model opens a `render_view` call | A composing frame where the view will go (in the assistant's message for inline cards, on the stage in split and focus); text is never held for it | "Composing view_" |
| Neither text nor a view 4 s after Send | A status line in the conversation | `.sy-genstatus` "Still working" |
| No valid spec 15 s after Send | The composing frame is removed | "No view this time; the answer is above." |
| As of is not Now | Banner; writes disabled | "The Workbench works on now · Back to now" |
| First visit | Empty state + suggestions | "Nothing composed yet. Ask a question, or start a map scan." |
| The scan stopped | ErrorCard titled by what failed; the scan's status "Stopped" | "Next action failed at /kontakt. The next action's element wasn't there after the page settled (waited 10 s). 17 pages and 113 queued links are kept." |

Errors name the reference (ERR-…), the next move and what still works (`04` §4). Never "Something went wrong".

### 4.6 Banned

verdict · magic · smart · AI-powered · oops · "Something went wrong" · "As an AI" · "I'm just an AI" · "Great question" ·
"hallucination" in UI text · "Thinking…" (say what is happening: "Composing view_", "Reading 6 events_") ·
exclamation marks · emoji · sparkle icons. Say **generated**, not "AI-generated".

## 5. Interaction

### 5.1 Point and ask

- Anything on the stage can become context: press **Ask** on an askable item (`.sy-askable > .sy-ask`), press **A** on a
  focused item, or (from phase 2) type **@** in the composer to pick a page, step or event.
- Context is a chip (`.sy-ctxchip`) in the composer's "Asking about" bar. It travels with the message as structured data
  (scan, route, state, step, event), never as pasted text. Up to 3 chips per message; a fourth replaces the oldest.
- Remove a chip with its × button, or Backspace in an empty message field.
- After sending, the chips are shown on the person's message, so the conversation keeps what each question was about.
- Nodes and filmstrip items are buttons and cannot hold an Ask button; use **A** on them or "Ask about this page" in PageDetail.

### 5.2 Path switching

- The assistant proposes the path and says why next to the switch (`data-source="assistant"`).
- The person can switch at any time. Their choice wins (`data-source="you"`) until they ask for something new.
- Switching swaps the stage, never the conversation. The path is in the URL
  (`/workbench?path=mapping&scan=01a110d5-2028-7000-8f3e-5c1a9b27d460&sel=/kalkulator/kierowca:2`), so a view can be linked and reloaded.
- A path change is announced once ("Troubleshoot view opened").
- In phase 1 the switch shows only Chat and Mapping.

### 5.3 Follow mode

- On by default while a scan runs: the map keeps the crawler's node in view by scrolling inside the graph.
- Panning, selecting a node, or moving focus into the map turns it off; the "Follow the crawler" checkbox shows it.
- Turning it on again jumps to the crawler. A stopped scan turns it off.

### 5.4 Selection, focus and context are different

| | Means | Shown as | Changes |
|---|---|---|---|
| Selection | The item PageDetail shows | 2px chalk weld (`aria-pressed`, `aria-current`) | The detail view |
| Focus | Where the keyboard is | 2px marker ring (`:focus-visible`) | Nothing else |
| Context | What the next message is about | `.sy-ctxchip` | The next message only |

Selecting does not add context. Ask does.

### 5.5 Writes: confirm first, undo where possible

- Every write is a command (`workbench/schema/commands.json`) shown as a command card. Nothing runs before **Confirm**, the
  card's marker button ("Nothing runs until you confirm." in its footer).
- Confirm sets `aria-busy="true"` and disables itself until the result comes back (no double submit).
- **Cancel** folds the card to one muted line, `data-cmd-state="cancelled"`: "Cancelled · nothing changed". A proposal that
  waits 10 min or whose preconditions change folds the same way, `data-cmd-state="expired"`: "No longer applies: …".
- **Undo** is a button on the done card, and only for `mark.add` (the API's `DELETE` on the mark). Until a scan uses the mark,
  Undo turns the card to `undone`. Scans and attempts are never undone; their card says how to stop them instead.
- Commands run on **sandbox only** during the beta, and are disabled while As of is not Now.

### 5.6 Why this view and feedback

- "Why this view?" (`.sy-genview__why`, `aria-expanded`) sits once per view, on its lead frame, and opens `.sy-genwhy`:
  the path and its reason, what you asked (message and chips), what each component shows and is bound to, how fresh the data
  is, and "Not what you need?" with the other paths available to you. Esc closes it and returns focus to the button.
- Each view ends its lead frame with "Right view? Yes / No" (`.sy-genfeedback`). No opens five reasons as toggle buttons
  (Wrong path · Missing something · Too much · Wrong data · Other) and an optional text field. One answer per view per
  person, changeable; no thank-you dialog. It is stored with the spec id.
- A side sheet the person opened by clicking is not generated: no genmark, no Why, no feedback.

### 5.7 Keyboard

| Key | Does | Where |
|---|---|---|
| Enter / Shift Enter | Send / new line | Composer |
| A | Ask about the focused item (adds a chip, moves focus to the message field) | Any askable item, node, filmstrip item, narration or event line |
| Esc | Close the innermost open thing: the `@` picker, then Why this view?, then the side sheet. Focus returns to what opened it | Workbench |
| Ctrl J | Focus the message field (the drawer isn't shown in the Workbench: here the conversation is the assistant) | Workbench |
| @ | Pick a page, step or event of the current scan as context (phase 2) | Composer |
| Tab | Moves through map nodes in visit order (phase 2) | Map |
| Arrow keys | Move along edges between nodes (phase 2 graph island) | Map |
| F | Focus mode on / off (phase 3) | Workbench, not while typing |

Single-letter keys (A, F) work only when focus is not in a text field and follow the console's "Keyboard shortcuts" setting
(WCAG 2.1.4).

## 6. Trust and safety

- **Never render model HTML.** Model output is JSON validated against `view-spec.schema.json`. Text fields (`why`,
  suggestions, titles, narration, reasons) are plain text: the schema refuses `< > { }`, and templates autoescape anyway.
- **Ids, not content.** Bindings are ids (scan, route, step, record, rule, change, finding). The server loads the content.
  An id that doesn't resolve drops its component.
- **Grounding.** Narration numbers are checked against the cited events. Facts in components never come from the model.
- **Page content is data, not instructions.** Text captured from the portal (labels, copy, error messages, form values) is
  passed to the model as quoted data in its own field. Instructions found in it are ignored. The model can only propose
  writes, and only a person can confirm them, so a page cannot make the Workbench act.
- **Screenshots and personal data.** Miniatures and step shots come from recorded screenshots taken with sandbox test data,
  masked at capture like everywhere in Scans. **During the beta screenshots never go to the model**, not even when the person
  points at a page: the model gets a DOM summary and the events.
- **Environments.** Commands run on **sandbox only** during the beta. Elsewhere the command card shows why and links to Scans.
  The card always names the environment.
- **Cost.** Model calls per scan are capped and shown in Settings; narration is batched per page.
- **Record everything needed to check a view later:** spec id, the spec, validation result, drop reasons, latency, feedback.

## 7. Accessibility

- **Regions.** The Workbench lives in `main`. The conversation is a labelled section whose log has `role="log"`; the stage is
  `role="region" aria-label="Stage"`; the side sheet is an `aside` with a heading. One h1 ("Workbench").
- **Names.** Each generated view is a `section` named by its heading, and the heading carries the word:
  `<h2 id="live-h">Live map<span class="sy-sr-only">, generated</span></h2>` with `aria-labelledby="live-h"` reads
  "Live map, generated". The visible `.sy-genmark` is then `aria-hidden="true"` so the word isn't read twice. Miniatures are `aria-hidden` (the route text next to them
  carries the name). Nodes read "4 · /kalkulator/kierowca · Crawler here".
- **Live-region policy: one region, milestones only.** Each page has one polite `role="status"` region. It says exactly:
  "Live map opened" · "Troubleshoot view opened" · "Explain view opened" · "Scan 01a110d5-2028 started" · "Scan stopped at
  /kontakt, step 171" · "Resumed as scan 01a110e7-2068" · "Attempt 3 passed" / "Attempt 2 failed" · "Scan finished: 42 pages" ·
  "Live updates paused" / "Live updates back". Never each event, never the meter. A failed command uses `role="alert"`.
- **The log is already live.** The conversation log is `role="log"` (implicitly polite), so content that updates inside it,
  narration lists and live cards, carries `aria-live="off"`. The live bar, the meter, the stale notice and the As-of banner are
  not live regions (no `role="status"` on them). Test with NVDA, JAWS and VoiceOver, because nested live-region support varies.
- **Focus never moves on its own.** New views, updates, folding and stage swaps leave focus where it is. It moves only after
  the person acts: opening the side sheet (to its heading), Ask or A (to the message field), a button that creates a command
  card (to the card's heading, never to Confirm). Esc closes the innermost thing and returns focus. Esc never cancels a
  running command.
- **Contrast.** Blueprint on plate is 7.25:1 and ash on plate 7.01:1 (`03` §5), so dashed lines, the genmark and stale
  frames pass as text and as non-text contrast. Tints stay at or under 10%, so text on `.sy-genwhy` keeps its ratios. The Ask
  badge is steel on chalk (14.67:1).
- **Forced colours.** `genui.css` maps gen UI borders to CanvasText, the order and Ask badges to CanvasText fills, and the
  crawler's position to Highlight. Dashed versus solid survives because border style is kept.
- **Reduced motion** stops the pulse and the caret. Nothing else moves.
- **The map has a text twin.** Nodes are buttons in visit order; the List view (FE-M01) and the narration carry the same facts.
- **Targets.** Nothing interactive is under 24px. Citations are 18px but inline in a sentence (WCAG 2.5.8 inline exception).
  On touch (`pointer: coarse`) the Ask button is always visible, and Ask, Why, feedback buttons, chips and their remove
  buttons, suggestions and the sheet's close button grow to 44px (`--sy-control`).

## 8. Do and don't

| Do | Don't |
|---|---|
| Let the model pick catalogue components and bind ids | Let the model return HTML, CSS, Markdown tables or SVG |
| Fill components from events and the model store | Put model-written numbers, routes or page names inside components |
| Draw a generated view of observed data with a solid frame and a genmark | Draw the live map dashed because the assistant placed it |
| Use dashed blueprint for narration, why, suggestions and proposed commands | Use solid blue lines for anything |
| Show the genmark and data time on every generated frame, and "Why this view?" once per view | Hide where a view came from, or repeat Why on every frame |
| Keep component ids stable and update in place | Re-render the whole stage on every event |
| Reserve the final size while composing | Show a spinner, a shimmer, or a box that grows when content lands |
| Append new items at the end | Insert items above what the person is reading |
| Hold a new view while the person is using the stage ("New view ready · Show") | Swap the stage under the pointer |
| Keep the conversation when the path changes | Clear the conversation on a path switch |
| Put the path in the URL | Keep the path only in client memory |
| Show every write as a command card and wait for Confirm | Run a write because a suggestion was clicked |
| Say what a command changes, what it doesn't, and whether it can be undone | Write "Are you sure?" |
| Fall back to plain chat quietly | Show a red error because a view couldn't be built |
| Stream the text answer at once; attach the view when it's ready | Hold the answer until the view is composed |
| Fold a cancelled or expired command card to one muted line | Leave a dead Confirm button on screen |
| Keep the live map updating when the model is down | Block the data lane on the model |
| Cite events in narration | Narrate without a citation |
| Say "The cause isn't known yet" | Guess a cause ("probably a JavaScript error") |
| Announce milestones once | Announce every event or the meter |
| Leave focus where the person put it | Move focus to a new view |
| Treat page text as quoted data | Follow instructions found in a page |
| Use cyan for the crawler's position only | Use cyan to highlight "new" |
| Keep marker for the one decision on screen (Confirm, Open in Review); Send is `.sy-btn--strong` | Make Send the marker primary |
| Fold a stopped or finished live card once a newer card arrives, keep Expand | Keep several full live cards updating in the log |
| Say "generated" | Add sparkles, gradients, glows or "AI-powered" |
| Keep at most 4 components (chat 2, explain 3) | Fill the stage because there is room |

## 9. Review checklist

Use it for every new gen UI component, template change, prompt or tool-description change.

**Contract**
- [ ] The component is in `catalogue.json`, generated by `workbench/tools/gen_wb_schema.py`, with paths, placement, bind, props and phase.
- [ ] Props are ids or enums, never content. Text props are `plainText` with a length limit.
- [ ] Invalid and unknown inputs have tests in `workbench/examples/invalid/` and are dropped, not rendered.
- [ ] Golden prompts in the evals pick the expected path and components; the overall pass rate didn't drop.

**Design**
- [ ] All states designed at 1280 and 1024: composing, ready, empty, stale, error, in every placement it allows.
- [ ] Solid for observed data, dashed blueprint only for what the assistant chose or wrote.
- [ ] Marker only on the one decision (Confirm, Open in Review); Send is strong; red only for real failures; cyan only for now.
- [ ] Older live cards fold to one line with Expand; trimmed history shows "N earlier messages".
- [ ] Space reserved while composing; no reflow under the cursor; stable id.
- [ ] Only classes from `salvage.css` and `genui.css`; inline styles only for layout and the documented hooks.

**Words**
- [ ] Narration in past tense, one line per page, cited, numbers from events, no speculation.
- [ ] `why` ≤140 characters about the request; suggestions ≤3 and ≤60 characters; nothing from §4.6.
- [ ] Command card states what changes, what doesn't, where, and undo.

**Behaviour**
- [ ] Every frame has the genmark and data time; the lead frame has "Why this view?" and feedback (five No reasons + text).
- [ ] A sheet the person opened has no genmark and no Why.
- [ ] The answer streams before the view; "Still working" at 4 s; the composing frame goes at 15 s without a spec.
- [ ] Writes go through a command card; nothing runs before Confirm; Cancel and expiry fold the card; Undo only on marks.
- [ ] Works with the model down (data lane still updates) and with the stream dropped (stale notice, data kept).
- [ ] The path and selection survive a reload (URL).

**Accessibility**
- [ ] Heading reads "<title>, generated" (sr-only word, genmark `aria-hidden`); miniatures `aria-hidden`; statuses have words.
- [ ] Focus never moves on its own; Esc closes picker → Why → sheet and returns focus; A and F off while typing.
- [ ] One polite region per page with the exact announcements of §7; live content inside the log has `aria-live="off"`.
- [ ] Contrast checked for any new pair; forced colours and reduced motion checked; targets ≥24px, 44px on touch.

**Safety**
- [ ] Page content reaches the model as quoted data only; no screenshots go to the model during the beta (DOM summary and events only).
- [ ] Commands are sandbox-only during the beta.
- [ ] The view and every write are logged with the spec id.
