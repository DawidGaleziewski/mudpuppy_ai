# Implementation Plan: Screenshots and Wireframes as Documentation Evidence

**Branch**: `feature/008-r20-r21-screenshots-wireframes` | **Date**: 2026-10-04 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/008-screenshots-wireframes/spec.md`

## Summary

Each newly recorded state gets an unmasked full-page PNG screenshot and a **layout** (the ARIA
tree with bounding boxes from Playwright's `ariaSnapshotJSON({ boxes: true })`, converted to page
coordinates). Both are taken in the same `record_state` phase as the ARIA snapshot, before any
action touches the page. Elements are identified by a deterministic **element key** (`role "name"`
plus `#n` for repeats in page order) that is computed the same way from the stored YAML snapshot
and from the layout tree. That one rule joins boxes, BA citations, dashboard highlights and
wireframe shapes.

A new pure package, `@pathfinder/wireframe`, turns a stored ARIA YAML snapshot into a fixed-style
SVG and an `.excalidraw` JSON file. The crawler generates both when it records a state, and the
`wireframes:build` command regenerates them. The BA cites a region of a screen with the new
evidence kind `screen_region`, which is a state id plus an element key. The dashboard gets a state
page and an image-only evidence route, and draws highlights as CSS overlays. `docs:export` copies
screenshots and wireframes into the export folder and writes deterministic highlight crops
(drawn with `pngjs`).

The constitution is at 2.0.0. Text scrubbing becomes a per-portal opt-in (`pii_scrub`, default
off). On non-production portals, map mode fills a form with deterministic test data before it
clicks the form's submit control. Production keeps refusing every non-read action.

## Technical Context

**Language/Version**: TypeScript 5 (Node 22, ESM) for the crawler workspace in `apps/crawler`;
Python 3.12 for the dashboard in `apps/dashboard`

**Primary Dependencies**: Playwright 1.63 (already used: `screenshot`, `ariaSnapshotJSON`), `yaml`
(already a dependency of `@pathfinder/config`), Kysely/better-sqlite3, the MCP SDK and Zod. One new
dependency: `pngjs` (MIT, pure JS, deterministic encoding) for export highlight crops. FastAPI,
Jinja2 and htmx for the dashboard. No Excalidraw package: the file format is written directly.

**Storage**: SQLite at `data/db/<env>.sqlite`. New migration `0006_screenshots_wireframes`. The
content-addressed evidence store (`data/evidence/`) gains binary blobs (`.png`, `.svg`,
`.excalidraw`, layout `.json`).

**Testing**: Vitest (unit tests for the pure packages, golden files for wireframes and highlight
crops, integration tests against the reference portal); pytest for the dashboard routes and
templates.

**Target Platform**: local developer machine (WSL2/Linux) with headless Chromium

**Project Type**: monorepo with a CLI and MCP servers (TS) plus a read-only web dashboard (Python)

**Performance Goals**: capture adds ≤ 1.5 s per *new* state (known states pay nothing); a
wireframe renders in under 50 ms per state.

**Constraints**: the export and the wireframes are byte-deterministic; dashboard GET routes never
write; screenshots are capped at 10 000 CSS px high; the evidence route serves only
`png`/`svg`/`excalidraw` refs that match the content-address pattern.

**Scale/Scope**: one reference-portal map is about 20–60 states, so about 20–60 PNGs of
0.2–2 MB each. Up to 400 boxed elements per state.

**Structure Decision**: all code stays in the existing apps (`apps/crawler`, `apps/dashboard`).
The only new package is `@pathfinder/wireframe`, kept pure and apart from the crawler so that the
CLI, the crawler and the docs export can all import it without pulling in Playwright. The Python
dashboard never renders wireframes or computes element keys. It serves the files the TypeScript
side produced and matches cited keys against the keys stored in the layout JSON.
