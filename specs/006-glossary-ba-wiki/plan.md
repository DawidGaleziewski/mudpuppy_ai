# Implementation Plan: Glossary and BA Wiki

**Branch**: `feature/006-r22-glossary-ba-wiki` | **Date**: 2026-10-03 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-glossary-ba-wiki/spec.md`

## Summary

One authored source under `docs/` (YAML entries, Markdown long pages and BA wiki pages with
citation front matter) explains the 59 terms the user rated Must/Nice in `term-review.md`. The
read-only dashboard loads it to show a Glossary page, wiki pages, `[?]` tooltips on labels and
one-line section intros, with no JavaScript needed. A console script generates the repository
README from the same source, and pytest checks keep templates, README and wiki citations in sync.
The Actions table's "Target" column becomes "Links to". A glossary-sync step joins the close-out
checklist. Details: [research.md](research.md).

## Technical Context

**Language/Version**: Python 3.13 (dashboard); content in YAML and Markdown

**Primary Dependencies**: FastAPI, Jinja2, Pydantic (existing); new: `pyyaml`, `markdown-it-py`

**Storage**: files under `docs/glossary/` and `docs/wiki/`; no SQLite change, no migration

**Testing**: pytest + ruff in `apps/dashboard`; `pathfinder-glossary --check`

**Target Platform**: local dashboard (127.0.0.1), modern browsers, phone width

**Project Type**: web app (server-rendered) plus authored documentation

**Performance Goals**: glossary parsed once at app start (and on reload in `--dev`); no per-request file I/O beyond wiki page reads

**Constraints**: read-only dashboard; no new front-end library; tooltips keyboard and touch reachable; Markdown rendered with raw HTML disabled; quotes ≤ 2 sentences

**Scale/Scope**: 59 entries, 2 long pages, 14 wiki pages, ~25 template label sites
