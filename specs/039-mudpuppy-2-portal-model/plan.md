# Plan 039: changing MudPuppy to the 2.0 system design

How the change in `design.md` is made: one branch, milestones M0–M7 each closed by its gate, a
clean store, and master untouched until 2.0.0 merges. Task ids are in `tasks.md`.

Migration 0037 is the `entity_refs` users in Layer B (`doc_evidence_links.ref_id`, `amendments.ref_id`, `about_ref` columns). On an empty store it can land in M1 with `entity_refs`; it is listed in M5 only because the Docs and amendments code switches there. Decide in T010 (db-admin): default M1.

**Order inside a milestone:** schema (db-admin agent) → pure functions with fixtures
(`@pathfinder/model`, `@pathfinder/fingerprint`) → writers (`@pathfinder/store`) → pipeline / tools
→ dashboard read models → gates and evals. One commit per task group, task ids in the message.

**Why this order:** capture first, because the model can only use what is recorded; the model
before interpretation, because deviations compare against a model version; rules and processes
need hypotheses; the classifier needs labels collected from M2.

## 2. Data reset (M0, FR-062)

Owner 2026-10-18: "This is all test data. We can drop it." Before anything else, with every
Pathfinder service stopped (chat service, MCP servers, dashboard, reference portal, proving ground;
kill by a printed list of their own PIDs, `feedback-kill-explicit-pids`):

| Path | Action | Why |
| --- | --- | --- |
| `data/db/*.sqlite*` | delete | v1 store; v2 schema drops its tables anyway |
| `data/evidence/` | delete | content-addressed files of v1 states |
| `data/traces/` (1.2 GB) | delete | Playwright traces of v1 runs |
| `data/exports/`, `data/mutation/`, `data/logs/`, `data/servers/` | delete contents | generated output |
| `data/gates/` | delete contents | regenerated by the gates |
| `data/evals/<portal>/` trial files | move to `data/evals/<portal>/history/v1/`; `baseline.json` → `history/v1/baseline.json` | keep the v1 numbers to compare against; v2 trials start a new baseline |
| `apps/crawler/evals/ground-truth/`, `reference-solutions/` (approved PROC-001 blueprint) | **keep** | repo files, the targets |
| `../export-fork` | keep; regenerated at M7 | field artifact, never fixed in place |
| `feature/038b-api-endpoint-kind` | keep parked; rebased after R-77 with a new migration number | owner's parking |

A script does it: `pnpm --dir apps/crawler store:reset --confirm` (T002), refusing while any
listed service port answers, printing what it deletes and the sizes, and writing
`data/RESET-v2.md` (date, git SHA, what was removed). Gitignored paths are removed from disk only;
tracked files (eval history moves) are committed.

Code and tables removed are listed in design § 17; their removal happens in the milestone that
replaces them, never earlier, so every commit builds (CLAUDE.md).

## 3. Working on one branch

- Branch `feature/039-r81-mudpuppy-2-portal-model`, cut from master at b904ebc.
- **Master during the work:** fixes only (`fix/…` branches merged to master as today). The 2.0
  branch rebases on master at the start of each milestone; conflicts are resolved on the branch.
- **Running the chat service:** never on this branch until M7 (memory: never run chat on an
  unmerged migration). Real-chat checks use a worktree, whose own `data/db/<env>.sqlite` is a throwaway store.
- **Commit tiers:** fast tier on every commit; the slow tier on every task touching
  `mcp-server/src/runtime/**`, `gates/**`, `crawler/src/**` or the proving ground (most of M1).
- **Milestone close:** gate green, `findings.md` updated (every bug and slip, with a test or eval
  idea, `log-every-bug-for-evals`), a session dump if stopping, a tag `v2.0.0-m<N>` on the branch
  (local, not pushed).
- **Merge:** after M7, squash to master as v2.0.0 (the pattern of v1.0.x merges), tag `v2.0.0`.

## 5. Constitution Check

| Principle | Effect | Status |
| --- | --- | --- |
| I Observed vs intent | hypotheses keep the three labels; derived facts are `inferred` with their rule | complies |
| II Evidence and traceability | every hypothesis and model object cites `entity_refs`; Layer A untouched | complies, strengthened |
| III Role separation | crawler emits hypotheses instead of `rule_candidates`; the headless driver runs replays through the same gated tools | **amendment 6.0.0 item 3** |
| IV Replay verification | `trace_runs.status` keeps `recorded → replay_verified → documented`, promoted by code | complies |
| V Safety | the driver is gated like the agent; limits unchanged; every transition keeps its safety class | complies |
| VI Human in the loop | derived facts apply without approval, reversible; everything else proposal-only; statuses derived from events | **amendment 6.0.0 item 2** |
| VII Deterministic core | reconciler, rules and planner are pure functions with fixtures; the miner is deterministic (fixed seeds) | complies |
| Technical: two layers | becomes three plus interpretation | **amendment 6.0.0 item 1** |
| Technical: Python | miner reads `mode=ro`, writes through `model:import` | **amendment 6.0.0 item 4** |
| Technical: storage | SQLite only; no new store | complies |

The amendment (design § 18) is written and approved in M0 (T003) before any M3 code.

## 6. Risks of the change itself

| Risk | Mitigation |
| --- | --- |
| A long-lived branch drifts from master | master takes fixes only; rebase per milestone; master's roadmap items that touch the same code wait for 2.0 |
| Big blast radius (~90 files read `edges`, ~80 `cluster_id`, ~45 `doc_evidence_links`) | replace per milestone with the replacing code; typecheck and the read-model drift tests catch leftovers; `rg` lists in `findings.md` per milestone |
| Reconciler bug poisons everything downstream | the four reconciler gates and the switchboard run in the slow tier from M2; `model:reconcile --rebuild` recovers |
| The BA guidance is frozen (R-77) | M5's guidance tasks are blocked until the owner's review (Q-1); M1–M4 do not touch `ba-practice` beyond tool names, which are listed for the review |
| UX designer late | functional Salvage Yard pages per milestone; the designer's pages replace them (T061) |
| Cost of eval trials | ~$7 per reference-insurer trial, one per milestone from M2, three at M7; switchboard gates cost no tokens |
| Python not installed where the reconciler runs | step 10 reports "miner not run"; rules and communities wait, nothing else breaks |
| Time | the largest change so far; M1, M2 and M5 are each the size of the largest v1 specs |
