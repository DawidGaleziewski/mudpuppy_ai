Under the hood

How the Workbench stays generative without becoming unpredictable: the assistant picks and fills components from a fixed catalogue; live data never passes through the model.

Two lanes: data and words

Scan engineEvery step is one event with an id (01a110d5#171).
→
Event stream (SSE)Server-sent events: one stream per Workbench tab, keyed by the conversation.
→
ComponentsLive map, meter, miniatures update themselves (htmx sse swap). No model in this lane.Fast · exact
YouMessage + context chips (page, step, scan).
→
AssistantPicks the path and returns a view spec + narration that cites event ids.Generated
→
ServerValidates the spec against the catalogue, renders the templates, binds them to the data lane.
→
ActionsWrites (resume, attempt, mark) become command cards. Nothing runs before Confirm; the result updates the card and the narration.

A view spec

From the assistant
{ "version": "1", "path": "mapping",
  "why": "You asked to map the OC/AC calculator.",
  "components": [
    {"id": "map", "type": "LiveMap", "bind": {"scan": "01a110d5"}, "props": {"follow": true, "view": "graph"}},
    {"id": "detail", "type": "PageDetail", "bind": {"scan": "01a110d5", "page": "@selected"}},
    {"id": "story", "type": "Narration", "bind": {"scan": "01a110d5"}, "props": {"every": "page"}}
  ] }
Checked against workbench/schema/view-spec.schema.json, then ids are resolved. Bad components are dropped, not the view; an empty list means plain chat.

Stack

Proposed
  • Server templates (Jinja) render every component; htmx swaps them in
  • Live data over SSE (htmx sse extension), resumable with Last-Event-ID
  • Small Web Components only where the client must think: map keyboard and follow
  • No React for the beta: no second rendering path, no build step, one CSS source (ADR-WB-1 says when to revisit)

Guardrails

  • Catalogue only: the model never writes HTML or CSS
  • Numbers and pages come from events, never from the model; narration cites event ids
  • Every generated panel says so ("generated") and answers "Why this view?"
  • Writes go through commands and ask first; Undo where possible
  • Focus never jumps; changes are announced once; reduced motion respected

Budgets

  • View spec → first paint< 300 ms
  • Live event → on screen< 1 s
  • Narration (model)batched per page
  • Model calls per scancapped, shown in Settings

How the beta proves itself

  • Time to answer "where is the crawler and is it stuck?"
  • Stops resumed or fixed without leaving the Workbench
  • Point-and-ask use per session
  • Path overrides (the assistant picked wrong) and fallbacks to chat
  • "Was this the right view?" on every generated panel
