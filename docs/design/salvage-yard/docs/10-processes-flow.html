How processes work now

A process is a named path through the portal for one persona. A is what the scans saw. B is what people draw over it. Every change is a new revision, the assistant only proposes, and scans tell you which variant each environment runs. Full spec: 10-processes.md.

02

Lifecycle

Stages are derived from data, never set by hand, and a process can move back (a scan detects a rollback).

SuggestedInferredThe assistant groups screens and says why. Nothing saved. Accept, Edit first or Dismiss.
ScopedA r1Accepted or created by hand (name, persona, start, end). A r1 built from the scans.
As-is documentedConfirmedEnd reached in a scan and the PROC record confirmed in Review.
To-be in designB r1+A to-be variant has a saved revision. Compare and spec available.
MigratingLive · sandboxA to-be variant is live in some environment (scan-detected or marked).
MigratedLive · productionThe to-be runs in production.
03

Who changes what

Scans

Observed
Create A revisions when the observed path changes or the end is first reached. Detect which variant each environment runs (live). Never touch B.

Assistant

Proposes
Suggests processes, with a Why line from links it saw. Proposes changes into your draft; drafts the PROC doc and the change spec text. Never saves a process, a revision or live status.

People

Decide
Accept, edit or dismiss suggestions; create scopes. Branch, draft and save B revisions; annotate steps One form instead of two. Compare, export, restore, mark live (confirmed). Can't edit A by hand. Branch instead.
